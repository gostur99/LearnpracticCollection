# Название - 000

## 1. Общие сведения
Каталогизатор личной коллекции с детальной аналитикой. Пользователь заводит элементы коллекции, привязывает к ним несколько жанров и авторов, проставляет статусы и оценки, а затем получает статистику. Необходима для удобного отслеживания потребляемого медиа (фильмов/книг/игр), а также для отслеживания собственных симпатий для лучшего выбора новых произведений.
Целевая аудитория: Пользователем буду я сам для составления списков просмотров сериалов и игр.

## 2. Функциональные требования
- Добавление элементов с привязкой к нескольким жанрам и авторам.
- Статусы: «В планах», «В процессе», «Завершено», «Брошено», а также изменение у элементов коллекции статусов и оценок.
- Фильтрация и сортировка (по году, оценке, жанру, статусу, автору).
- Поиск по названию.
- Аналитика: общее количество, средняя оценка, топ-10 авторов/жанров, распределение по статусам.
- Управление категориями (добавление, редактирование и удаление авторов и жанров).

## 3. Нефункциональные требования
- Язык интерфейса: русский.
- Производительность: время отклика интерфейса — не более 1 секунды при стандартных операциях.
- Хранение данных: локально в файле БД (SQLite), сеть не используется.
- Защита от ошибок: нельзя сохранить элемент без названия и года, нельзя сохранить элемент без привязки к жанру или автору (может быть указан как народное творчество или неизвестен), нельзя удалить автора или жанр, который связан с произведением (без подтверждения).
- Инициализация БД: при первом запуске приложение само создаёт таблицы из встроенного SQL-скрипта.

## 6. Сценарии использования

**Сценарий 1: Добавление нового элемента в коллекцию**
Актёр: Пользователь
Предусловие: Приложение запущено. В базе данных SQLite уже существуют справочники статусов, а также нужные авторы и жанры.
Основной поток:
1. Пользователь нажимает кнопку «Добавить элемент».
2. Система отображает форму ввода со следующими обязательными полями: Название, Год выпуска, Статус, Жанры, Автор(ы), а также поле оценки.
3. Пользователь вводит название элемента, указывает год, выставляет оценку и выбирает из выпадающего списка один из четырёх статусов.
4. Пользователь выбирает из списков жанры и авторов для этого элемента.
5. Пользователь нажимает кнопку «Сохранить».
6. Система проверяет заполнение обязательных полей (выводит "Необходимо заполнить Х поле") и локально записывает данные в таблицы items, item_genres и item_authors.
7. Система закрывает форму и выводит сообщение: «Элемент успешно добавлен в коллекцию».

**Сценарий 2: Изменение статуса и оценки элемента**
Актёр: Пользователь
Предусловие: Приложение запущено, в коллекции есть хотя бы один элемент.
Основной поток:
1. Пользователь кликает по строке элемента в таблице коллекции.
2. Система открывает форму редактирования с уже заполненными полями.
3. Пользователь меняет статус (например, с «В планах» на «В процессе») и корректирует оценку.
4. Пользователь нажимает «Сохранить».
5. Система обновляет данные в таблице items в БД.
6. Система закрывает форму и обновляет строку в таблице коллекции.

**Сценарий 3: Поиск, фильтрация и сортировка**
Актёр: Пользователь
Предусловие: Приложение запущено, в БД есть элементы с разными жанрами, авторами, годами и статусами.
Основной поток:
1. Пользователь открывает главный экран «Коллекция».
2. Пользователь вводит часть названия в строку поиска.
3. Пользователь выбирает из выпадающих списков конкретный Жанр, Автора, Статус и указывает Год.
4. Пользователь выбирает направление сортировки.
5. Пользователь нажимает кнопку «Применить».
6. Система формирует SQL-запрос с учетом всех условий.
7. Система отображает в таблице только те элементы, которые удовлетворяют заданным критериям.
Альтернативный поток: Если ничего не найдено, система отображает пустую таблицу и сообщение «По вашему запросу ничего не найдено». Кнопка «Сбросить» возвращает полный список.

**Сценарий 4: Просмотр аналитики**
Актёр: Пользователь
Предусловие: Приложение запущено, в коллекции добавлены элементы с оценками и статусами.
Основной поток:
1. Пользователь переходит на вкладку «Аналитика».
2. Система выполняет SQL-запросы к БД для подсчета статистики.
3. Система вычисляет общее количество элементов и среднюю оценку (округляет до 1 знака).
4. Система формирует топ-10 авторов и топ-10 жанров (вычисляется AVG(rating) только по элементам с имеющимися оценками. При равенстве средних оценок сортировать по количеству завершённых произведений (COUNT)).
5. Система подсчитывает количество элементов в каждом из 4-х статусов.
6. Система отображает все данные на экране.
Альтернативный поток: Если коллекция пуста, система отображает нули, чтобы избежать ошибки деления на ноль.

**Сценарий 5: Управление категориями (с защитой от ошибок)**
Актёр: Пользователь
Предусловие: Приложение запущено, открыта вкладка «Управление категориями».
Основной поток:
1. Пользователь переключается на вкладку «Авторы» или «Жанры».
2. Пользователь нажимает кнопку «Удалить» рядом с нужной записью.
3. Система проверяет в БД, привязан ли этот автор/жанр к каким-либо элементам.
4. Если запись не привязана, система удаляет её из БД и обновляет список на экране.
Альтернативный поток: Если автор/жанр привязан к произведению, система блокирует удаление и выводит окно подтверждения: «Этот автор связан с произведениями, они удалятся с ним. Продолжить?». При отказе пользователя удаление отменяется.

## 7. Критерии приёмки
- [ ] Пользователь может успешно сохранить новый элемент, заполнив обязательные поля (Название, Год, Статус) и связав его минимум с одним жанром и одним автором.
- [ ] При попытке сохранить элемент без названия, жанра или автора, система блокирует сохранение и выводит сообщение об ошибке.
- [ ] Система корректно сохраняет и отображает элемент, если к нему привязано несколько авторов и несколько жанров одновременно.
- [ ] Для произведений без конкретного автора есть возможность выбрать заглушки «Неизвестен» или «Народное творчество».
- [ ] Элементу можно присвоить только один из четырёх статусов: «В планах», «В процессе», «Завершено», «Брошено». Изменение статуса корректно перезаписывается в БД.
- [ ] Поиск по названию работает по частичному совпадению строки (инвариантно к регистру символов).
- [ ] Комбинированные фильтры (одновременно по жанру + статусу + году + автору) и сортировка выдают математически точный результат выборки.
- [ ] Экран аналитики корректно рассчитывает и отображает общее количество элементов (целое число), среднюю оценку (дробное число, округленное до 1 знака), топ-10 авторов и жанров, а также наглядное отображение количества элементов в каждом из **4-х** статусов.
- [ ] При первом запуске в корневой папке автоматически создается файл БД SQLite с правильной структурой таблиц. Приложение не падает с ошибкой.
- [ ] Для работы приложения доступ к интернету или сети не требуется.
- [ ] При попытке удалить автора или жанр, который привязан хотя бы к одному элементу, система выдает запрос на подтверждение.
- [ ] Система требует подтверждений на удаление любых элементов коллекции.
- [ ] Отклик не более 1 секунды для аналитики, фильтрации и поиска при 1000 элементах коллекции.
