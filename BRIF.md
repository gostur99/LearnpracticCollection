Название - 000
-Каталогизатор личной коллекции с детальной аналитикой. Пользователь заводит элементы коллекции, привязывает к ним несколько жанров и авторов,
проставляет статусы и оценки, а затем получает статистику. необходима для удобного отслеживания потребляемого медиа (фильмов/книг/игр),
отслежживания собственных симпатий для лучшего выбора новых произведений.
-Пользователем буду я сам для составления списков просмотров сериалов и игр

2. Функциональные требования:
-Добавление элементов с привязкой к нескольким жанрам и авторам.
-Статусы: «В планах», «В процессе», «Завершено», «Брошено» и изменение у элементов коллекции статусов и оценок.
-Фильтрация и сортировка (по году, оценке, жанру, статусу).
-Поиск по названию.
-Аналитика: общее количество, средняя оценка, топ-10 авторов/жанров, распределение по статусам.

3. Нефункциональные требования
-Язык интерфейса: русский.
-Производительность: время отклика интерфейса — не более 1 секунды при стандартных операциях.
-Хранение данных: локально в файле БД (SQLite), сеть не используется.
-Защита от ошибок: нельзя сохранить элемент без названия и года, нельзя сохранить элемент без привязки к жанру или автору 
(может быть указан как народное творчество или неизвестен), нельзя удалить автора, который связан с произведением (без подтверждения).
-Инициализация БД: при первом запуске приложение само создаёт таблицы из встроенного SQL-скрипта.

7. Сценарии использования
-Сценарий 1: Добавление нового элемента в коллекцию
Актёр: Пользователь
Предусловие: Приложение запущено. В базе данных SQLite (автоматически созданной локально при старте) уже существуют справочники статусов, а также нужные авторы и жанры.
Основной поток:
1. Пользователь нажимает кнопку «Добавить элемент».
2. Система отображает форму ввода со следующими обязательными полями: Название, Год выпуска, Статус, Жанры, Автор(ы),а так же поле оценки.
3. Пользователь вводит название элемента, указывает год, при желании выставляет оценку и выбирает из выпадающего списка один из четырёх статусов (например, «В процессе»).
4. Пользователь выбирает из списков два жанра и двух авторов (соавторов) для этого элемента.
5. Пользователь нажимает кнопку «Сохранить».
6. Система проверяет заполнение обязательных полей (выводит "Необходимо заполнить Х поле") и локально записывает данные в таблицы items, item_genres и item_authors.
7. Система закрывает форму и выводит сообщение: «Элемент успешно добавлен в коллекцию».

Сценарий 2: Изменение статуса и оценки элемента
Актёр: Пользователь
Предусловие: Приложение запущено, в коллекции есть хотя бы один элемент.
Основной поток:
Пользователь кликает по строке элемента в таблице коллекции (или нажимает «Изменить»).
Система открывает форму редактирования с уже заполненными полями (Название, Год, Жанры, Авторы).
Пользователь меняет статус (например, с «В планах» на «В процессе»), а также при необходимости корректирует оценку.
Пользователь нажимает «Сохранить».
Система обновляет данные в таблице items в БД.
Система закрывает форму и обновляет строку в таблице коллекции.
Альтернативный поток: если пользователь вводит недопустимое значение оценки (например, текст вместо цифры), система выводит сообщение «Оценка должна быть числом» и блокирует сохранение.

Сценарий 3: Поиск, фильтрация и сортировка
Актёр: Пользователь
Предусловие: Приложение запущено, в БД есть элементы с разными жанрами, авторами, годами и статусами.
Основной поток:
Пользователь открывает главный экран «Коллекция».
Пользователь вводит часть названия в строку поиска.
Пользователь выбирает из выпадающих списков конкретный Жанр, Автора, Статус и указывает Год.
Пользователь выбирает направление сортировки (например, по оценке от большего к меньшему).
Пользователь нажимает кнопку «Применить».
Система формирует SQL-запрос с учетом всех условий и сортировки.
Система отображает в таблице только те элементы, которые удовлетворяют всем заданным критериям.
Альтернативный поток: Если по заданным параметрам ничего не найдено, система отображает пустую таблицу и выводит сообщение «По вашему запросу ничего не найдено». Кнопка «Сбросить» возвращает полный список.

Сценарий 4: Просмотр аналитики
Актёр: Пользователь
Предусловие: Приложение запущено, в коллекции добавлены элементы с оценками и статусами.
Основной поток:
Пользователь переходит на вкладку «Аналитика».
Система выполняет SQL-запросы к БД для подсчета статистики.
Система вычисляет общее количество элементов и среднюю оценку (округляет до 1 знака).
Система формирует топ-10 авторов и топ-10 жанров на основе наивысших оценок.
Система подсчитывает количество элементов в каждом из 4-х статусов.
Система отображает все данные на экране.
Альтернативный поток: Если коллекция пуста, система отображает нули (0 элементов, средняя оценка «—»), чтобы избежать ошибки деления на ноль.

Сценарий 5: Управление категориями (с защитой от ошибок)
Актёр: Пользователь
Предусловие: Приложение запущено, открыта вкладка «Управление категориями».
Основной поток:
Пользователь переключается на вкладку «Авторы» или «Жанры».
Пользователь нажимает кнопку «Удалить» рядом с нужной записью.
Система проверяет в БД, привязан ли этот автор/жанр к каким-либо элементам в таблицах item_authors или item_genres.
Если запись не привязана, система удаляет её из БД и обновляет список на экране.
Альтернативный поток (Защита от ошибок): Если автор/жанр привязан хотя бы к одному произведению, система блокирует удаление и выводит окно подтверждения: «Этот автор связан с произведениями в вашей коллекции. Удаление невозможно без подтверждения (или приведет к потере связей). Продолжить?». При отказе пользователя удаление отменяется.

9. Критерии приёмки
-Пользователь может успешно сохранить новый элемент, заполнив обязательные поля (Название, Год, Оценка, Статус) и связав его минимум с одним жанром и одним автором.
При попытке сохранить элемент без названия, жанра или автора,система блокирует сохранение и выводит сообщение о ошибке
-Система корректно сохраняет и отображает элемент, если к нему привязано несколько авторов (например, соавторы книги) и несколько жанров одновременно
-Для произведений без конкретного автора должна быть возможность выбрать заглушки «Неизвестен» или «Народное творчество»
-Элементу можно присвоить только один из четырёх статусов: «В планах», «В процессе», «Завершено», «Брошено». Изменение статуса корректно перезаписывается в БД
-Поиск по названию работает по частичному совпадению строки (инвариантно к регистру символов)
-Комбинированные фильтры (одновременно по жанру + статусу + году) и сортировка (по оценке от большего к меньшему и наоборот) выдают математически точный результат 
выборки
-Экран аналитики корректно рассчитывает и отображает общее количество элементов в коллекции (целое число), среднюю оценку всех элементов 
(дробное число, округленное до 1 знака после запятой),топ-10 авторов и топ-10 жанров на основе наивысших оценок, 
наглядное отображение количества элементов в каждом из 3-х статусов
-При самом первом запуске приложения в корневой папке автоматически создается файл базы данных SQLite с правильной структурой таблиц 
(items, authors, genres, item_genres, item_authors, statuses). Приложение не падает с ошибкой отсутствия таблиц
-Для выполнения любых функций (включая запуск, сохранение и аналитику) доступ к интернету или сети не требуется.
-При попытке удалить автора или жанр, который привязан хотя бы к одному элементу коллекции система выдает запрос на подтверждение
-Система требует подтверждений на удалениелюбых элементов
-Отклик не более 1 секунды для аналитики, фильтрации и поиску при 1000 элементах коллекции
